# Notion — командное пространство и синхронизация

Notion выполняет роль командного слоя экосистемы: базы данных проектов и задач плюс публикация избранных заметок из Obsidian. Локальная работа ведётся в Obsidian, в Notion попадает только то, что помечено к публикации.

## Структура рабочего пространства

| База данных | Назначение |
|-------------|-----------|
| **Research Projects** | Исследовательские проекты, статьи, гранты: статус, дедлайны, ответственные |
| **Integration Tasks** | Задачи по интеграции экосистемы (10 задач) со статусами |
| **Obsidian Notes** (страница-контейнер) | Родительская страница для заметок, публикуемых из Obsidian |

## Настройка интеграции

1. Создайте internal-интеграцию на [notion.so/my-integrations](https://www.notion.so/my-integrations) и скопируйте токен.
2. Сохраните токен в переменной окружения (уровень пользователя, не в коде):

   ```powershell
   [Environment]::SetEnvironmentVariable('NOTION_TOKEN', 'ntn_xxx', 'User')
   ```

3. Предоставьте интеграции доступ к родительской странице: в Notion откройте страницу-контейнер → `•••` → *Connections* → выберите интеграцию.
4. Укажите ID родительской страницы, под которой будут создаваться заметки:

   ```powershell
   [Environment]::SetEnvironmentVariable('NOTION_OBSIDIAN_PARENT_PAGE', '<page-id>', 'User')
   ```

   ID — это 32-символьный фрагмент из URL страницы.

> **Безопасность:** токен даёт запись в ваше рабочее пространство. Не коммитьте его в репозиторий и не передавайте в параметрах командной строки в общих окружениях.

## Синхронизация Obsidian → Notion

Скрипт [`scripts/Sync-ObsidianToNotion.ps1`](../scripts/Sync-ObsidianToNotion.ps1) публикует заметки, помеченные тегом `#publish` (см. [docs/obsidian.md](obsidian.md)).

```powershell
# Предпросмотр без обращений к API
.\scripts\Sync-ObsidianToNotion.ps1 -DryRun

# Обычная синхронизация: только изменённые #publish-заметки
.\scripts\Sync-ObsidianToNotion.ps1

# Полная пересинхронизация всех #publish-заметок
.\scripts\Sync-ObsidianToNotion.ps1 -Force

# Синхронизировать все заметки, игнорируя тег #publish
.\scripts\Sync-ObsidianToNotion.ps1 -AllNotes
```

### Как это работает

1. **Отбор.** Сканируется хранилище; служебные папки (`.obsidian`, `.git`, `templates`, `archive`) пропускаются, берутся только заметки с пометкой публикации.
2. **Детекция изменений.** Для каждого файла считается MD5-хеш и сравнивается с состоянием прошлой синхронизации (`~\.laptop-ecosystem\sync-state.json`) — неизменённые файлы пропускаются.
3. **Конвертация.** Markdown преобразуется в блоки Notion: заголовки H1–H3, абзацы, маркированные и нумерованные списки, чекбоксы, цитаты, разделители, блоки кода. YAML-frontmatter отсекается.
4. **Публикация.** Если страница для заметки уже существует (ID хранится в состоянии), её содержимое обновляется на месте; иначе создаётся новая страница под родительской. Дубликаты не создаются.
5. **Rate limiting.** Между запросами к API выдерживается пауза 350 мс (лимит Notion — 3 запроса/с).

### Ограничения

- Максимум **100 блоков** на страницу за один запрос; более длинные заметки усекаются с предупреждением.
- Инлайн-форматирование (жирный, курсив, ссылки) переносится как обычный текст.
- Синхронизация односторонняя: правки, сделанные в Notion, будут перезаписаны при следующем обновлении заметки из Obsidian.

### Диагностика

| Симптом | Причина и решение |
|---------|-------------------|
| `NOTION_TOKEN environment variable not set` | Задайте токен (шаг 2 настройки) и перезапустите терминал |
| `API token is invalid` | Токен отозван или скопирован с ошибкой — создайте новый |
| Страницы не появляются под нужной страницей | Не задан `NOTION_OBSIDIAN_PARENT_PAGE` или интеграции не выдан доступ к странице |
| Заметка не синхронизируется | Проверьте пометку публикации; убедитесь, что файл не в исключённой папке |
| Нужно пересоздать всё с нуля | Удалите `~\.laptop-ecosystem\sync-state.json` и запустите с `-Force` |
